# 剧本杀门店 AI 运营系统项目上下文

更新时间：2026-09-26

## 项目定位

面向剧本杀门店的 AI 运营辅助系统，帮助店长完成 DM 推荐、场次执行、玩家反馈分析和 DM 改进任务管理。

## 核心用户

- 店长：查看推荐、复核 AI 分析、发送改进任务、进行现场考核。
- 客服：录入玩家反馈、协助发送任务和维护记录。
- DM：接收改进建议并执行现场改进。
- 玩家：提供六维评分和具体文字反馈。

## 核心流程

```text
创建场次
→ 计算DM推荐
→ 店长安排DM
→ 开始/结束场次
→ 录入玩家评价
→ AI或本地规则分析
→ 店长确认/驳回分析
→ 聚合同DM同类问题
→ 达到阈值生成改进任务
→ 店长设置考核方式和日期
→ 发送给DM并进入执行中
→ 现场考核
→ 通过/失败/部分改善/无法判断
```

## 已实现或已验证能力

- SQLite 运行时主数据库，CSV 仅用于初始化和备份。
- DM、剧本、场次、玩家需求、反馈、推荐、AI分析和改进任务数据结构。
- 日期、时间、可主持剧本、场次冲突等硬性筛选。
- 六维匹配分、评分可信度和最终推荐分。
- 场次创建、安排DM、开始和结束场次。
- 玩家六维评价和文字反馈录入。
- OpenAI兼容接口适配；无Key时使用本地规则兜底。
- AI结果人工复核、确认和驳回。
- 近30天同DM同问题聚合。
- 高2次、中3次、低4次分别触发改进任务。
- 改进任务的现场考核字段和考核结果接口。
- 隔离数据库端到端测试。

## 当前设计原则

- AI只提供初步分析，店长保留业务判断权。
- 待复核和已驳回的分析不能参与改进任务聚合。
- 现场考核是改进任务的主要结论来源，后续场次评价用于持续监控。
- 发送给DM即视为DM已确认并进入执行中，不增加额外确认步骤。

## 真实性边界

- 当前是个人 V1 Demo，使用模拟门店数据。
- 尚未宣称真实门店部署或经营效率提升。
- 尚未完成真实 DM、店长和玩家用户验证。
- RAG、云部署、真实问卷 webhook、权限和生产监控不是当前已完成能力。
- 不得在简历或作品集中把规划功能写成已上线功能。
