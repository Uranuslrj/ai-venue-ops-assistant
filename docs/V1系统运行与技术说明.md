# 剧本杀门店 AI 运营系统 V1

## 已完成部分

### 1. SQLite 数据库

程序启动时会读取原有 8 张 CSV，并生成：

```text
script_kill_ops.sqlite3
```

SQLite 适合当前个人项目和 Demo，因为它不需要单独安装数据库服务，也方便以后迁移到 PostgreSQL、MySQL 或云数据库。

### 2. 推荐计算引擎

接口：

```text
GET /api/recommend?request_id=REQ001
```

处理顺序：

```text
当前可用状态
→ 日期可出勤
→ 时间段可用
→ 能主持该剧本
→ 检查未完成场次冲突
→ 计算六维匹配分
→ 计算评分可信度
→ 计算最终推荐分
→ 输出排序和推荐理由
```

计算公式：

```text
匹配分 = Σ（DM六维刷新评分 × 玩家需求权重）
最终推荐分 = 匹配分 × 评分可信度
```

### 3. 近30天同类问题聚合

接口：

```text
GET /api/aggregate
```

系统将同一DM、同一问题类型的评价放在同一组中，使用近30天作为窗口。

触发规则：

```text
高严重度累计2次 → 生成改进建议
中严重度累计3次 → 生成改进建议
低严重度累计4次 → 生成改进建议
```

单条评价涉及安全、歧视或重大服务失误时，可以由店长人工升级，不受累计次数限制。

### 4. 大模型接口适配

程序支持 OpenAI 兼容的 Chat Completions 接口：

```text
OPENAI_API_KEY=你的密钥
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=你的模型名称
```

有 Key 时，文字评价可以交给大模型做问题维度、问题类型、证据、严重程度和建议提取。

没有 Key 时，程序自动使用本地关键词规则完成 Demo，不会伪造大模型调用结果。因此当前页面可以直接验收，但不能把无Key时的规则结果宣传成真实大模型结果。

### 5. 浏览器运营页面

页面功能：

- 选择玩家需求和场次；
- 点击计算DM推荐；
- 查看硬性筛选、匹配分、可信度、最终分和推荐理由；
- 聚合近30天同类问题；
- 查看改进任务。

## 技术栈

- Python 3：后端服务和业务逻辑；
- `sqlite3`：本地关系型数据库；
- `http.server`：轻量HTTP服务；
- HTML/CSS/JavaScript：前端页面；
- `urllib.request`：调用大模型兼容接口；
- CSV：现有数据导入和备份格式。

没有使用第三方框架，目的是让 Demo 能够在低配置环境直接运行。正式生产版本可以换成 FastAPI、React 和 PostgreSQL。

## 运行方法

在 `work` 目录运行：

```powershell
python .\\app.py
```

浏览器打开：

```text
http://127.0.0.1:8765
```

## 云数据库迁移说明

当前已完成 SQLite 数据库落地和 `/api/export` 数据导出接口。由于云数据库服务商、账号、网络和表结构规范尚未确定，不能在没有凭证的情况下直接连接真实云数据库。

迁移时主要替换：

1. 数据库连接函数；
2. 建表脚本；
3. 环境变量中的数据库地址；
4. 生产环境的权限和备份策略。

当前业务计算逻辑不需要重写。
